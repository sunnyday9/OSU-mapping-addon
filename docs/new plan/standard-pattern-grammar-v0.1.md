# osu! AI Mapper — Standard Pattern Grammar v0.1

## 1. Purpose

This document defines the first ruleset-specific mapping vocabulary for osu!standard. It separates rhythm from 2D geometry and from slider construction, allowing the same MappingIntent to be rendered in multiple styles.

## 2. Design Principles

1. Pattern family expresses mapping intent, not raw coordinates.
2. Movement is parameterized separately from rhythm.
3. Geometry must be generated by deterministic algorithms.
4. Slider paths are a separate rendering concern from the high-level movement pattern.
5. Distance, angle, direction changes and flow are explicit constraints.
6. Style may bias geometry choices but must remain downstream of Base Mapping Intelligence.

## 4. Shared Rhythm Parameters

```yaml
rhythm:
  subdivision: 1/1 | 1/2 | 1/3 | 1/4 | 1/6 | 1/8 | 1/12 | 1/16 | custom
  swing: 0..1
  accent_strength: 0..1
```

## 5. Shared Movement Parameters

```yaml
movement:
  direction: none | up | down | left | right | diagonal_up | diagonal_down | custom
  distance: 0..1
  angle: 0..360
  curvature: 0..1
  flow: 0..1
  reversal_rate: 0..1
```

The normalized `distance` parameter is resolved by the generator using playable-field dimensions and difficulty constraints. It is not a direct osu! coordinate.

## 6. Single

### Intent

A single hit-object sequence representing isolated beats or sparse musical events.

```yaml
family: single
rhythm:
  subdivision: 1/1 | 1/2 | 1/4 | 1/8
movement:
  direction: custom
  distance: 0..1
```

## 7. Jump

### Intent

Two simultaneous or closely paired objects used to express stronger musical accents or spatial emphasis.

```yaml
family: jump
rhythm: 1/2 | 1/4 | 1/8
movement:
  distance: 0..1
  angle: 0..360
pair_shape: horizontal | vertical | diagonal | custom
```

The generator must ensure both objects remain playable and should reject degenerate spacing.

## 8. Stream

Continuous or semi-continuous sequences in which object placement primarily communicates rhythmic continuity.

```yaml
family: stream
rhythm:
  subdivision: 1/4 | 1/8 | 1/12 | 1/16
movement:
  direction: flow | up | down | left | right | custom
  distance: 0..1
  reversal_rate: 0..1
```

The generator may produce circles and slider transitions, but raw slider geometry is still downstream.

## 9. Burst

A short, locally dense sequence used for accents or escalation.

```yaml
family: burst
count: 3..12
subdivision: 1/8 | 1/12 | 1/16
shape: line | diagonal | arc | zigzag
```

## 10. Jumpstream

A continuous stream with controlled jump accents.

```yaml
family: jumpstream
rhythm:
  subdivision: 1/8 | 1/16
jump_ratio: 0..1
movement:
  flow: 0..1
  distance: 0..1
```

The generator must avoid accidental repeated impossible jumps caused by independent placement of neighboring objects.

## 11. Slider Chain

A sequence where slider direction and path are used to express a sustained musical phrase.

```yaml
family: slider_chain
rhythm:
  subdivision: 1/2 | 1/4 | 1/8
movement:
  direction: flow | reverse | custom
  distance: 0..1
  curvature: 0..1
slider:
  duration_beats: 1/4 | 1/2 | 1 | 2 | custom
  shape: line | arc | bezier | custom
```

The slider path generator is responsible for fitting the shape to the play field.

## 12. Geometry Grammar

### Line

```yaml
shape: line
start_anchor: point
end_direction: vector
length: normalized
```

### Diagonal

```yaml
shape: diagonal
angle: 15..165
length: normalized
```

### Triangle

```yaml
shape: triangle
size: normalized
orientation: 0..360
```

### Arc

```yaml
shape: arc
radius: normalized
angle_span: 20..340
orientation: 0..360
```

### Zigzag

```yaml
shape: zigzag
segments: 2..12
amplitude: normalized
angle: 0..360
```

## 13. Movement Constraints

The validator should expose at minimum:

- consecutive jump distance
- object-to-object distance
- angle changes
- reversal frequency
- local spacing variance
- overlapping/unreachable placements
- excessive repetition of the same spatial structure

These constraints must be evaluated separately from star rating.

## 14. Transition Grammar

Supported v0.1 transition labels:

```text
same_shape
shape_change
flow_increase
flow_decrease
spacing_increase
spacing_decrease
angle_change
reversal
slider_entry
slider_exit
movement_reset
accent_land
```

Examples:

```text
stream → jump             : accent_land
line → diagonal           : shape_change
small movement → wide     : spacing_increase
slider_chain → stream     : slider_exit
flow → reversal            : reversal
```

## 15. Generator Contract

A Standard pattern provider consumes:

```text
PatternIntent
+ MusicTimeline
+ DifficultyProfile
+ Previous concrete objects
+ play-field constraints
```

and returns:

```text
ConcreteObject[]
+ PatternIssue[]
```

All coordinate generation must be deterministic for a fixed seed and inputs.

## 16. Slider Rendering Boundary

Pattern grammar specifies that a slider should exist and what its movement should mean. The final curve, control points, repeats and exact path are generated by a dedicated slider renderer.

This keeps the LLM/Planner from emitting raw slider control points and makes later style transformations possible.

## 17. Standard MVP Pattern Set

The first implementation should only require:

```text
single
jump
stream
burst
jumpstream
slider_chain
line
diagonal
arc
zigzag
```

Triangle, rotation, spiral and more specialized geometry can be added after the MVP proves the architecture.
